# Why 404, not 403? (plain English)

- Document type: Study note for the RBAC pack (not a test case)
- Standard(s) cited: Supports REQ-RBAC-03 / RSK-ISO-02; HTTP semantics used as a test oracle
- Product: VaultGrid (**fictional / fake data**)
- Cycle / version: Cycle 59
- Author role: Senior QA Analyst
- Status: Draft — human sign-off required

---

HTTP codes are the **expected result**. Testers must know what each one *tells the caller*.

| Code | Plain meaning | What the caller learns |
| --- | --- | --- |
| **401** | You are not logged in (or the token is bad). | “I am not authenticated.” |
| **403** | You are logged in. We **know that object**. Your **role** is not allowed to do this. | “That file exists. I am just not allowed.” |
| **404** | As far as you are allowed to know, **there is nothing here**. | “I cannot tell this ID from a random ID that never existed.” |

## Two different mistakes (both are in the case pack)

**Same company, wrong job (use 403).**  
You work at NORTHWIND as **Read-only**. The file is NORTHWIND’s file. You must not download the original. The API should say **403**: “We have that file. You may not download it.” That is TC-RBAC-006.

**Other company (use 404).**  
You still work at NORTHWIND. You guess (or paste) a file ID that belongs to **GLOBEX**. The API must **not** say 403. 403 would mean: “Yes, GLOBEX has a file with that ID. You just cannot open it.” A bad actor can harvest IDs that way. That leak is called an **existence oracle**. The API should say **404**, with **no** filename, hash, or tenant name — the same shape as an ID that never existed. That is TC-RBAC-004.

## Tiny picture

Think two offices with locked cabinets.

- **403:** “That folder is in *your* office. Your badge is not allowed to open it.” You learned the folder is real.
- **404:** “We will not confirm any folder with that number.” You learned nothing about the other office.

**200** with the other company’s data is the worst fail (the file came back).  
**403** on the other company’s ID is a quieter fail (you learned it exists).  
**404** with an empty body is the pass for cross-tenant.

## What to say in the interview (memorise this)

“403 means the object exists and my role is wrong. That is correct **inside** my tenant. **Across** tenants I expect 404, so I cannot tell a real foreign ID from a fake one. I still expect a deny line in **my** tenant’s audit.”
